## 99.99% SLA 到底承诺什么

99.99% 在线率听起来很漂亮，但真正有用的是看它怎么定义“不可用”，以及什么情况被排除在外。

搬瓦工的 SLA 是按**单台符合条件的 VPS、按自然月**计算。官方定义中，只有当 VPS 因搬瓦工网络或物理宿主机问题，从公网无法通过标准网络检查持续超过 1 分钟，并且不属于排除情况时，才会计入不可用时间。这个 SLA 不是按照整个账户、整个机房或所有服务一起计算。

99.99% 在线率大约对应每月 4 分 32 秒的可计入停机时间。超过这个阈值后，用户可以申请服务时长补偿，但不是自动发放现金退款。

官方补偿梯度如下：

| 当月可计入停机时间 | 服务时长补偿 |
| --- | ---: |
| 超过 4 分 32 秒但少于 10 分钟 | 12 小时 |
| 10 至 59 分钟 | 72 小时 |
| 60 至 119 分钟 | 120 小时 |
| 120 至 239 分钟 | 240 小时 |
| 240 至 419 分钟 | 360 小时 |
| 420 分钟或以上 | 1 个自然月 |

补偿形式是延长对应 VPS 的预付服务时间，不能兑换现金，也不能转移到其他 VPS 或账户。每个月的补偿上限是一整个月服务时长。

### 哪些情况不算 SLA 停机

以下情况通常不会计入 SLA：

- 提前至少 24 小时通知的计划维护；
- 单次不超过 10 分钟的紧急维护；
- 操作系统、应用程序、脚本、DNS、防火墙或 SSH 配置造成的问题；
- 超出套餐设计或公平使用政策的资源消耗；
- DDoS、DoS、黑洞路由、流量过滤或安全事件；
- VPS 被入侵、感染恶意软件或违反服务条款；
- 上游网络、互联网骨干线路或用户本地网络的问题；
- IP 被政府、监管机构或其他第三方封禁、过滤或列入黑名单；
- 欠费、账户暂停、法律或执法要求；
- 地震、洪水、战争、大规模电力或通信基础设施故障等不可抗力。

这意味着 DC5 SLA 更像是一套针对主机和服务商网络可用性的补偿机制，而不是“网站永远在线”的保险。比如服务器本身正常，但你的程序崩溃、数据库锁死、证书过期或域名解析错误，这些通常都不属于 SLA 赔付范围。

申请补偿时，需要通过支持渠道明确提出 **SLA Service Credit**，并提供受影响 VPS、停机时间、故障描述，以及可用的监控截图、日志或网络记录。申请期限是相关停机月份结束后的 90 天内。普通提交一张“服务器打不开”的工单，并不自动等于提出 SLA 补偿申请。

## 哪个 DC5 SLA 套餐更适合你

### 20G：适合小型生产服务

20G 套餐有 1 GB 内存、2 个 AMD 独享核心和每月 1 TB 流量。它可以用于：

- 个人 API；
- 小型企业官网；
- 轻量级反向代理；
- 监控节点；
- 低访问量的业务后台；
- 需要更稳定网络的测试环境。

但 1 GB 内存并不宽裕。运行数据库、面板、缓存、Web 服务和日志系统时，需要控制组件数量，最好使用轻量化配置。它不适合直接承担访问量较高的电商站点。

### 40G：入门业务的平衡点

40G 提升到 2 GB 内存和 3 个独享核心，月流量也达到 2 TB。对于 WordPress、小型 SaaS 后端、企业 API 和中小流量网站来说，资源余量比 20G 更好。

如果你已经确认需要 DC5 SLA，但还不确定业务会不会快速增长，40G 是比较容易理解的起步方案。它的价格仍然远低于 80G 以上套餐，同时拥有相同的机房、网络方向和 SLA 体系。

### 80G：更适合长期运行的网站

80G 配置为 4 GB 内存、4 个独享核心、80 GB 存储和 3 TB 月流量。它更适合：

- 中小型电商网站；
- 多容器部署；
- WordPress 加缓存和数据库；
- API 网关；
- 定时任务较多的业务；
- 需要保留更多日志和临时文件的服务。

这一级别开始，资源配置对生产环境更友好。若网站需要同时运行 Nginx、PHP、MySQL、Redis、监控和备份任务，80G 通常比 20G 或 40G 少很多资源管理上的妥协。

### 160G 与 320G：面向更重的应用栈

160G 有 8 GB 内存、6 个独享核心和 5 TB 流量，320G 则提升到 16 GB 内存、8 个独享核心和 8 TB 流量。这两档适合更重的后台、多个服务组合、较大的数据库缓存或需要一定并发能力的 API。

但“独享 CPU”不代表应用本身无需优化。数据库索引、连接池、缓存策略、磁盘 I/O 和备份方式仍然会决定实际表现。把低效代码直接放进更大的 VPS，通常只能延后问题出现，不能解决问题。

### 640G 及以上：高流量或高资源业务

640G、1280G 以及 HIBW 高流量方案提供 32 GB 或 64 GB 内存、10 Gbps 端口和 10 TB 至 20 TB 月流量。它们针对的是更重的电商平台、数据处理服务、API 集群节点或流量消耗明显的业务。

这些方案的价格已经不是普通个人 VPS 的范围。除非你确实需要更大的内存、更多独享 CPU、10 Gbps 端口或更高月流量，否则没有必要因为“配置看起来很强”就直接购买最高档。服务器配置越大，备份、监控、故障切换和应用运维也越需要规范。

## DC5 SLA 的线路适合中国用户吗

从官方网络描述来看，DC5 SLA 面向中国方向提供三网优化：

- 电信使用 CN2 GIA / CTGNet；
- 联通使用 Premium 线路；
- 移动使用 CMIN2；
- 同时提供多个 100Gbps 上行链路和自动故障切换。

这类线路设计对中国大陆访问美国洛杉矶服务器的用户更有针对性，尤其适合需要访问稳定性和跨境链路质量的站点、API 或后台服务。

不过，线路名称不能直接等同于“所有地区低延迟”。北京、上海、广州、成都、新疆等不同地区的运营商出口不同，晚高峰拥塞情况也不同。中国电信用户的表现不一定等于中国移动用户，家庭宽带也不一定等于云厂商线路。

比较稳妥的判断方式是：

1. 先确认你的主要访客或 API 调用方来自哪个地区；
2. 使用测试 IP 或已购买实例检查三网延迟与丢包；
3. 在工作日白天和晚高峰分别测试；
4. 观察持续连接、下载、HTTPS 请求和实际业务接口，而不是只看一次 Ping；
5. 为数据库、对象存储和备份准备独立方案，避免把所有数据放在单台 VPS 上。

“线路优化”解决的是网络路径问题，“SLA”解决的是特定范围内的可用性补偿问题，两者不是同一件事。

## 购买前容易忽略的限制

### SLA 不负责应用故障

搬瓦工的服务是自管理模式，用户需要自行负责操作系统、Web 服务、数据库、程序部署、备份恢复和安全配置。官方服务条款明确表示，服务商负责宿主机和基础设施，但不会替用户管理 VPS 内的软件环境。

因此，购买 DC5 SLA 后仍然应该配置：

- 独立的站点监控；
- 外部 HTTP 和 TCP 探针；
- 数据库备份；
- 异地备份；
- 日志轮转；
- SSH 密钥登录；
- 防火墙规则；
- 软件更新与漏洞修复；
- 至少一套应急恢复流程。

### DDoS 不属于 SLA 保障范围

官方 SLA 将 DoS、DDoS、攻击引发的流量过滤、限速、黑洞路由等情况列为排除项，并且明确说明 SLA 套餐不包含 DDoS 防护。

如果你的业务经常面对攻击流量，应该单独采购 CDN、清洗、防护或上游网络服务。DC5 SLA 的 99.99% 承诺不能替代专业的攻击防护。

### IP 更换不等于无限规避问题

DC5 SLA 提供每两周一次免费 IP 更换，这对 IP 被误封、信誉异常或业务迁移时有一定帮助。不过，频繁更换 IP 并不能解决违规内容、恶意流量、邮件滥发或程序被入侵等根本问题。服务条款仍然禁止垃圾邮件、端口扫描、恶意软件、开放代理、挖矿、未授权内容分发等活动。
